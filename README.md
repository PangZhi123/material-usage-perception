# 物料使用情况智能感知

通过施工现场视频识别、跟踪混凝土运输车辆，结合相机标定和作业区域配置，判断车辆作业过程，形成物料使用事件与估算结果。

## 设计思路

系统将视频输入、场景配置、分析任务和结果查询分开管理。实时视频与历史录像共用检测、跟踪、位置转换、区域状态判断和物料估算流程。

前端负责选择视频、标注对应点、划定作业区域和展示结果；后端负责保存配置、调度任务、执行分析及提供结果。物料用量根据车辆作业事件与容量等配置估算。

每次新建配置保留独立版本，任务启动时固定配置快照，便于按任务 ID 追溯分析条件和结果。

## 第一版的五个功能

### 1. 相机管理

登记相机 ID 与视频流地址，为实时分析和配置关联提供入口。相机 ID 用于识别视频来源，并关联对应的场景配置。

### 2. 实时物料监测

选择相机及适用配置，启动实时分析。系统检测、跟踪车辆，将画面位置转换到场景坐标，判断车辆进入、停留和离开作业区域的过程，推送车辆状态、轨迹及物料估算事件。

同一相机同时只允许一个实时任务，可请求停止并查看任务状态。

### 3. 历史视频分析

上传历史视频或注册服务器已有视频时，相机 ID（`cameraId`）选填，无需预先登记相机。不填写时视频不关联相机，接口返回 `cameraId: null`。随后选择录像适用的已有标定与作业区域配置版本，或新建配置，再启动分析。

历史分析独立运行，不占用实时相机。**第一版同时只允许一个历史分析任务**；已有任务运行或正在停止时，需等待任务结束或停止完成后再启动。历史与实时任务可以同时运行。

事件和轨迹时间按录像开始时间加视频内时间计算。用户可在启动时填写录像开始时间，未填写时使用视频登记时间字段 capturedAt；必须提供有效的带时区录像时间。

### 4. 物料结果查询

查询车辆作业事件、物料估算量、汇总统计及轨迹。实时和历史结果统一保存，通过任务 ID 区分分析批次，结合时间、相机、区域等条件查询。

结果保留任务和配置版本信息，方便回看每次分析使用的条件。检测结果默认每 10 帧采样保存，可按任务分页查询，供前端绘制检测框；默认文件存储支持服务重启后重新加载结果。

### 5. 场景管理

管理场景图片、相机画面与场景之间的标定关系，以及作业区域、车辆容量和作业判定参数。

通过对应点建立位置转换关系，通过区域多边形定义作业范围。配置以多个版本保留，用户可为实时画面或历史录像选择适用版本，也可新建配置。

## 2026-11-06 更新

历史视频上传（`POST /videos`）和服务器视频注册（`POST /video-registrations`）的 `cameraId` 改为选填；未关联相机的视频仍支持重复文件去重。测试页面及接口测试说明已同步更新。创建历史分析任务仍使用 `videoId` 和 `configurationId`，不提交 `cameraId`；创建配置时的相机字段规则保持不变。

## 2026-11-03 更新

历史分析已取消对相机 ID 的占用及同一视频专属配置的限制，支持复用配置版本并保存任务配置快照；新增录像开始时间输入，并提供简单测试前端。
