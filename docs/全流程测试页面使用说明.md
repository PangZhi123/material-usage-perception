# 全流程测试页面

页面随现有 FastAPI 后端提供，访问 `/test-console/`，直接调用同源真实接口，不需要安装前端依赖或另启前端服务。

## 启动

在项目根目录 PowerShell 中运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\start_test_console.ps1
```

访问 `http://127.0.0.1:8001/test-console/`。如 8001 已被占用，可加 `-Port 8002`；如果是在已有服务器上更新代码，重启后端后使用原服务地址的 `/test-console/`。脚本默认仅监听本机；如需局域网使用可显式传入 `-BindAddress 0.0.0.0`。

脚本默认使用 `models/best.pt`，服务器视频允许目录设为 `test-data`；已有对应环境变量时沿用已有设置。视频上传、场景、配置和结果存放在现有后端的数据目录中。

## 建议首次测试步骤

1. 点击“检查后端”，确认后端正常、模型就绪。历史分析只需要相机 ID，例如 `CAM_TEST_1`，没有实时地址时可以跳过相机登记。
2. 打开“历史分析”，选择 `test-data/test-video.mp4`，点击“上传并注册”。也可以先选择本地同一视频供预览，再用“服务器视频登记”填写 `test-video.mp4`；重新选择本地文件会清空视频与配置 ID，需要重新登记或从视频列表选择。
3. 视频预览出现后，点击“截取当前帧”，页面自动进入场景管理，并绑定注册得到的 videoId。
4. 点击“上传场景”，再点击“同视角四角标定”。此快捷方式仅适用于从同一帧产生的左右两图，不能用于真实俯视场景图。
5. 选择画布模式“作业区域”，在右图依次点击至少三个顶点，围住要测试的车辆地面行驶或停留区域。默认区域不自动填充，避免把整个画面当作计量区。
6. 设置容量及进入、停留、离开参数，点击“验证标定并保存配置”。为了快速联调，可以手动调低最低作业时长，例如 5 秒；这是测试参数，需要实际进入和离开才会有相应事件。
7. 返回历史分析，核对自动填入的视频与配置 ID，点击“启动历史分析”。共用监控区显示真实帧对象、跟踪 ID、状态和报文，可请求停止或重新订阅任务。
8. 在结果查询中设置包含任务执行时间的范围，读取事件、统计。当前后端历史任务的事件时间基于录像开始时间加视频时间，查询时不按原视频画面中印刷的日期填写。点击事件的“查看轨迹”，绘制该访问的场景轨迹；支持分页读取轨迹及导出当前页事件和统计 JSON。

历史视频的播放预览独立于后台推理，不保证与帧报文同步。没有完整进出过程时，统计可能为零，不能仅以是否出现非零方量判断页面成功。

## 五个功能的可测范围

| 功能 | 当前页面可测试 | 仍需条件或尚未支持 |
| --- | --- | --- |
| 相机管理 | 登记、以同 ID 更新流地址、选择浏览器登记引用 | 真实连通性需在线流；相机删除和服务端设备全量清单尚无接口；API 登记在服务内存中，重启需重新登记或配置 YAML |
| 场景管理 | 上传 / 读取图片，双图对应点标定，多边形区域，计量与状态机参数，保存配置 | 当前一个配置仅支持一个区域；页面记录不是服务端全量场景列表 |
| 实时分析 | 启动真实相机任务、订阅推送、读取状态、停止任务；无流时可用历史任务验证共用监控区 | RTSP/RTMP 取流、断流重连和实际延迟需真实源；页面不直接播放 RTSP；视频配置不可用于相机流 |
| 历史分析 | MP4 上传、去重注册、服务器视频登记、浏览器预览截帧、真实推理、任务停止和监控 | 推理依赖可用模型；服务器登记不自动提供浏览器视频播放 |
| 结果查询 | 时间 / 相机 / 区域 / 状态筛选，事件翻页、统计分组、轨迹绘制及 JSON 导出 | 查询最长 31 天；统计累计有效完成事件；导出事件限当前查询页 |

浏览器本地保存最近 50 条相机、场景、配置和任务引用，方便继续测试；这些引用不代表服务器当前有效记录。已知场景、配置和任务均可通过实际接口核对。流地址不保存在浏览器操作记录中。

## 验证

```powershell
python -m pytest tests/test_console.py tests/test_api_v1.py tests/test_api.py -q
node --check src/material_usage_perception/api/static/app.js
```

`tests/test_console.py` 覆盖页面静态资源、空视频清单、缺失引用错误、场景上传后读取、标定配置保存后读取和持久任务状态读取。现有接口测试覆盖历史分析及结果推送等链路。浏览器完整交互与真实实时流需现场复核。

## 历史分析更新

历史任务可复用所选相机配置版本，不再要求配置绑定同一视频。也可新建配置或自行选择其他配置。每次新建保留原配置；任务保存配置快照，不受后续配置变化影响。

启动前填写录像开始时间（浏览器本地时间，提交时携带时区）；接口字段为 recordingStartedAt。省略时使用视频登记的 capturedAt，两者均无有效带时区时间则拒绝启动。事件及轨迹时间使用录像开始时间加视频内时间，任务 startedAt 仍表示实际执行时间。

本版全局只允许一个历史任务运行或停止中，不占用实时相机；实时任务继续按相机互斥。历史和实时结果保存在一起，按 taskId 区分。
