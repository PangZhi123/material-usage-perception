# 2026-11-03 修改记录

## MP0203 任务冲突

原实现中，实时相机任务和历史视频任务均使用 `camera:{cameraId}` 作为互斥资源。只要同一资源存在 QUEUED、RUNNING 或 STOPPING 任务，新任务就返回 HTTP 409 / MP0203。因此同一相机的实时任务会阻止历史分析；调用停止接口后，任务尚未退出、仍为 STOPPING 时也会继续冲突。

本次历史任务改用独立资源 `history:single`，实时任务继续按相机互斥。本版全局最多运行一个历史任务，历史与实时任务可同时运行。历史任务运行或停止中，新历史任务会收到 MP0203，应等待完成或停止完成后重试。错误信息透传调度层原因，测试页面增加限制提示。

停止接口仍是异步请求，不代表后台已经退出。本次未专门修复取流/推理卡住、旧任务状态残留或服务重启恢复；现场若持续 STOPPING，应进一步检查，不能将所有 MP0203 都视为已解决。

## 历史分析流程调整

- 历史任务使用用户指定的配置版本，取消配置必须绑定相同 videoId 以及视频 cameraId 必须匹配配置的任务创建限制；可复用相机配置或自行选择配置，也保留新建配置流程。
- 实时任务仍校验相机匹配，且不能使用视频专属配置。
- 提交实时和历史任务时深拷贝配置并保存 configurationSnapshot，执行使用该快照；新建配置仍产生独立 ID，保留原配置记录。
- 新增 recordingStartedAt（带时区）；历史任务未传时使用视频 capturedAt，两者均无有效带时区时间则拒绝启动。
- 历史事件、轨迹和帧 capturedAt 以录像开始时间加视频内时间计算；任务 startedAt 继续表示实际执行时间。
- 历史及实时结果继续保存在现有结果体系中，以 taskId 区分，不另设存储。
- 检测、跟踪、空间投影、状态机及物料估算公式未改动，调整的是配置、任务调度和时间输入。

## 后续更新：算法结果持久化

相机信息由业务后端管理，本次不增加相机登记持久化。

默认文件仓库已补充启动读取：恢复任务、配置、场景、视频元数据、事件与轨迹。重启前仍为 QUEUED/RUNNING/STOPPING 的任务标为 FAILED，不自动续跑，已有部分结果保留。

任务选项新增 `options.sampleEveryFrames`（默认 10，范围 1–10000），从第 1 个处理帧起每隔指定帧数保存一次，独立于 WebSocket 推送节流，空对象帧也保存。目录为 `outputs/backend_data/tasks/{taskId}/frames/{seq}.json`，保留帧时间、视频内时间、尺寸、车辆框、跟踪 ID、置信度、场景位置及状态等结果，不保存逐帧图像或完整 WebSocket 消息。

- `GET /api/material-perception/v1/tasks/{taskId}/frames?fromSeq=0&limit=100`：读取采样检测结果，返回 items、hasMore、nextFromSeq。前端可据 bboxPx/bboxNorm 绘制框，据视频内时间定位录像。采样帧间不提供逐帧准确框。
- `GET /api/material-perception/v1/tasks/{taskId}/result`：读取任务信息及该任务事件，estimatedVolumeM3 汇总 COMPLETED 事件；录像开始时间、执行时间与配置快照从 task 获取。

结果按任务 ID 保存。采样保存失败使任务失败，避免无提示丢失存档。上述采样落盘和启动恢复针对默认 FilesystemRepository；其他可注入仓库暂不提供采样存档。

验证：完整测试 67 passed，包含重启加载、任务结果查询、采样分页和中断任务恢复测试。未验证真实模型视频及浏览器回放绘制。
