# 2026-11-03 修改记录

## MP0203 任务冲突

原实现中，实时相机任务和历史视频任务均使用 `camera:{cameraId}` 作为互斥资源。只要同一资源存在 QUEUED、RUNNING 或 STOPPING 任务，新任务就返回 HTTP 409 / MP0203。因此同一相机的实时任务会阻止历史分析；调用停止接口后，任务尚未退出、仍为 STOPPING 时也会继续冲突。

本次历史任务改用独立资源 `history:single`，实时任务继续按相机互斥。本版全局最多运行一个历史任务，历史与实时任务可同时运行。历史任务运行或停止中，新历史任务会收到 MP0203，应等待完成或停止完成后重试。错误信息透传调度层原因，测试页面增加限制提示。

停止接口仍是异步请求，不代表后台已经退出。本次未专门修复取流/推理卡住、旧任务状态残留或服务重启恢复；现场若持续 STOPPING，应进一步检查，不能将所有 MP0203 都视为已解决。

## 历史分析流程调整

- 历史任务使用用户指定的配置版本，取消配置必须绑定相同 videoId 以及视频 cameraId 必须匹配配置的任务创建限制；可复用相机配置或自行选择配置，也保留新建配置流程。
- 实时任务仍校验相机匹配，且不能使用视频专属配置。
- 提交实时和历史任务时深拷贝配置并保存 configurationSnapshot，执行使用该快照；新建配置仍产生独立 ID，保留原配置记录。
- 新增 recordingStartedAt（带时区）；历史任务未传时使用视频 capturedAt，两者均无有效带时区时间则拒绝启动。
- 历史事件、轨迹和帧 capturedAt 以录像开始时间加视频内时间计算；任务 startedAt 继续表示实际执行时间。
- 历史及实时结果继续保存在现有结果体系中，以 taskId 区分，不另设存储。
- 检测、跟踪、空间投影、状态机及物料估算公式未改动，调整的是配置、任务调度和时间输入。
