物料使用情况智能感知后端——历史视频上传/注册接口测试说明
版本日期：2026-09-01

一、功能说明

后端现已支持两种历史视频注册方式：

1. 页面或客户端上传 MP4 文件
   POST /api/material-perception/v1/videos

2. 注册后端服务器本地已有的 MP4 文件（不复制文件）
   POST /api/material-perception/v1/video-registrations

两种方式注册成功后都会返回 videoId。前端随后把该 videoId 传给“分析任务控制”接口即可开始历史视频分析。

注册信息保存在 SQLite 数据库中，同时加入当前服务的运行时注册表；不需要修改 YAML，也不需要重启服务。服务重启后，已成功注册的视频仍可通过原 videoId 使用。


二、方式一：上传历史视频

请求：
POST http://<后端IP>:<端口>/api/material-perception/v1/videos
Content-Type: multipart/form-data

表单字段：
- file：必填，MP4 视频文件；当前仅支持 .mp4。
- cameraId：必填，视频所属摄像头标识，长度 1～64 个字符。
- capturedAt：选填，视频采集时间，建议使用带时区的 ISO 8601 格式，例如 2026-09-01T08:00:00+08:00。

curl 示例：
curl -X POST "http://192.168.10.32:8001/api/material-perception/v1/videos" -F "file=@D:/test/history.mp4;type=video/mp4" -F "cameraId=CAM_TEST_1" -F "capturedAt=2026-09-01T08:00:00+08:00"

Swagger 测试步骤：
1. 打开 http://<后端IP>:<端口>/docs。
2. 展开 POST /api/material-perception/v1/videos。
3. 点击 Try it out。
4. 选择 MP4 文件，填写 cameraId；capturedAt 可不填。
5. 点击 Execute。
6. HTTP 状态码应为 201，并保存响应 data.videoId。

成功响应 data 示例：
{
  "videoId": "video_0123456789abcdef",
  "cameraId": "CAM_TEST_1",
  "originalFileName": "history.mp4",
  "contentType": "video/mp4",
  "sizeBytes": 12345678,
  "sha256": "...",
  "width": 1920,
  "height": 1080,
  "fps": 25.0,
  "frameCount": 7500,
  "durationSec": 300.0,
  "capturedAt": "2026-09-01T08:00:00+08:00",
  "uploadedAt": "...",
  "status": "READY",
  "deduplicated": false
}

说明：
- 文件采用分块方式写入，不会一次性把整个视频加载到内存。
- 相同文件、相同 cameraId 重复上传时，返回原 videoId，deduplicated=true，不重复占用磁盘空间。
- 相同文件使用不同 cameraId 注册时，会返回新的 videoId，但复用同一个物理文件。
- 默认最大文件为 5 GiB，可通过 MATERIAL_PERCEPTION_MAX_VIDEO_BYTES 调整。
- 当前流程为“上传完成并通过视频解码校验后，再返回 videoId 并开始分析”，暂不支持普通 MP4 未上传完成时边传边分析。


三、方式二：注册服务器本地已有视频（不复制）

此方式适用于视频文件已经在运行算法后端的服务器上。先在启动服务前设置允许访问的根目录：

PowerShell 示例：
$env:MATERIAL_PERCEPTION_LOCAL_VIDEO_ROOT="D:\\shared-videos"

请求：
POST http://<后端IP>:<端口>/api/material-perception/v1/video-registrations
Content-Type: application/json

请求体示例：
{
  "cameraId": "CAM_TEST_1",
  "relativePath": "project-a/history.mp4",
  "capturedAt": "2026-09-01T08:00:00+08:00"
}

若根目录为 D:\\shared-videos，上述请求实际读取：
D:\\shared-videos\\project-a\\history.mp4

注意：
- relativePath 必须是相对于允许根目录的路径，不能传绝对路径。
- 禁止使用 .. 越过允许根目录。
- 文件必须位于算法后端所在服务器，并且后端进程具有读取权限。
- 此方式直接读取原文件，不会再复制一份，因此原文件不能被移动或删除。


四、使用 videoId 创建历史分析任务

取得 videoId 后，调用：
POST /api/material-perception/v1/tasks
Content-Type: application/json

请求体示例：
{
  "cameraId": "CAM_TEST_1",
  "configurationId": "<已存在且有效的配置ID>",
  "inputType": "VIDEO_FILE",
  "videoId": "video_0123456789abcdef",
  "options": {
    "persistTrajectory": true,
    "pushIntervalMs": 1000
  }
}

预期结果：任务创建成功，不再出现“videoId is not registered”错误。

重要：创建任务时的 cameraId 必须与上传/注册视频时填写的 cameraId 一致；configurationId 必须是后端已经存在的有效配置标识。


五、建议验收用例

1. 上传一个有效 MP4，确认返回 201、status=READY 和 videoId。
2. 使用返回的 videoId 创建 VIDEO_FILE 任务，确认任务能够进入分析流程。
3. 使用相同 cameraId 再次上传同一文件，确认 videoId 不变且 deduplicated=true。
4. 重启后端，再次使用原 videoId 创建任务，确认仍可解析。
5. 注册服务器本地 MP4，确认文件没有被复制，并可使用返回的 videoId 创建任务。
6. 上传非 MP4、空文件或损坏 MP4，确认接口拒绝请求。
7. 本地注册时传绝对路径或越界路径，确认接口拒绝请求。
8. 创建任务时使用不匹配的 cameraId，确认后端拒绝请求。


六、常见问题

1. 提示 videoId is not registered
   请确认使用的是上传/注册接口成功响应中的 data.videoId，不要使用本地文件名代替；同时确认前端和任务接口访问的是同一个后端实例及数据库。

2. 提示 local MP4 video is not readable
   检查 MATERIAL_PERCEPTION_LOCAL_VIDEO_ROOT、relativePath、文件扩展名、文件是否存在以及后端进程的读取权限。

3. 上传成功但任务创建失败
   检查 cameraId 是否与注册时一致、configurationId 是否有效，并查看任务接口返回的 code 和 message。

4. 是否需要修改 YAML 或重启
   不需要。新视频由接口写入 SQLite 并立即注册；YAML 仅保留用于预配置的开发测试视频。
